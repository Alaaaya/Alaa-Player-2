# Theme Architecture Requirements

## الهدف

يدعم Alaa Player عشرين تجربة عرض مستقلة وظيفياً. لا تغيّر الثيمات بيانات IPTV أو الشبكة أو المشغّل أو التخزين، لكنها تغيّر طبقات العرض والتنقل والتركيز والحركة بالكامل.

> الثيم ليس مجموعة ألوان. يجب أن يشعر المستخدم عند تغييره أنه انتقل إلى تطبيق IPTV آخر، مع بقاء مصدر البيانات والمنطق نفسه.

## عقد البيانات المشترك

تعتمد جميع الثيمات على تدفقات البيانات الحالية للقنوات والأفلام والمسلسلات والحلقات والمفضلة وسجل المشاهدة وEPG. يمنع تثبيت أسماء قنوات أو وسائط أو بيانات تجريبية في مكوّنات الثيم.

| المجال | يظل مشتركاً وغير قابل للاستبدال من الثيم |
| --- | --- |
| بيانات IPTV | M3U وXtream وStalker وJellyfin وبيانات API وJSON الحالية. |
| المنطق | المستودعات وViewModels وRoom وDataStore والمزامنة ونسخ البيانات. |
| التشغيل | Media3 ومصادر البث ومسارات الاستعادة والمفضلة وسجل المشاهدة. |
| العرض | التخطيطات والـnavigation chrome والبطاقات والتركيز والحركة واللاعب هي القابلة للاستبدال حسب الثيم. |

## عقد Live TV الإلزامي

مهما اختلف الثيم، تظل شاشة البث المباشر مرتبطة بالبيانات الحية وتضم فئات وقائمة قنوات **عمودية** ومعاينة القناة وبيانات EPG والبحث والمرشحات والمفضلة. يمنع تحويل القنوات إلى شبكة.

| العنصر | الشرط |
| --- | --- |
| القنوات | قائمة عمودية قابلة للتركيز بالـDPAD، تعرض الرقم والشعار والاسم والبرنامج والحالة عند توفرها. |
| الفئات | مرتبطة بالمزود الحالي، قابلة للبحث والتركيز والقفل والمفضلة وفق المنطق القائم. |
| المعاينة | تستخدم القناة المركزة وبياناتها الحية؛ تتغير مواضعها وهيكلها حسب الثيم فقط. |
| الأداء | قوائم Lazy وصور مخزنة مؤقتاً وانتقالات خفيفة مناسبة لـAndroid TV. |

## التبديل والحفظ

يظهر كل ثيم في إعدادات التطبيق باسم ووصف ومعاينة فعلية. يحفظ الاختيار في DataStore، ويبدل التطبيق إلى مكونات العرض والتنقل واللاعب الخاصة بالثيم، مع الاحتفاظ بحالة المستخدم وبياناته.

## عقد التنقل والـDPAD

يعرّف كل ثيم navigation chrome خاصاً به، مثل rail أو top bar أو navigation فضائي، لكنه يربط المقاصد نفسها ولا يكرر حالة الشاشة. تنتقل مفاتيح الاتجاهات بين مناطق التركيز وفق خريطة الثيم، مع ضمان طريق Back واضح إلى المقصد السابق وعدم احتجاز التركيز في لوحة أو حوار.

| الموقف | السلوك المشترك |
| --- | --- |
| دخول قسم رئيسي | يظهر محتوى القسم فقط ولا تبقى واجهة Home مركبة تحته. |
| Live TV | ينتقل التركيز بين الفئات والقائمة العمودية والمعاينة وفق ترتيب الثيم. |
| Player | تعيد Back المستخدم إلى route المصدر أو القسم المنطقي نفسه. |
| الحوارات | تبدأ من عنصر واضح، وتستعيد التركيز إلى المصدر عند الإغلاق. |

لكل ثيم نظام تركيز وحركة مستقل، مثل توهج أو إطار أو ارتفاع أو انتقال سينمائي، لكن يجب أن تبقى الحركة قصيرة وقابلة للمقاطعة وتعتمد على `transform` و`opacity` قدر الإمكان.

## عقد المشغّل ووضع ملء الشاشة

يحافظ جميع الثيمات على محرك Media3 ومصادر البث ومسارات الصوت والترجمة والجودة، بينما تستبدل مكوّنات العرض فقط. يحدد كل ثيم تخطيطاً منفصلاً للـoverlay، مثل شريط سفلي أو لوحة جانبية أو عناصر زجاجية عائمة أو HUD، ويعرض عند توفر البيانات اسم القناة أو الوسيط والحالة المباشرة والبرنامج الحالي والتالي وtimeline والصوت والترجمة والجودة والمفضلة والانتقال السابق/التالي والإرشاد الكامل.

لا يسمح للثيم بإخفاء وظائف المشغّل القائمة أو تغيير حالة التشغيل نتيجة تغيير تصميمه. تكون عناصر التحكم متاحة بالـDPAD وتستخدم مهلة ظهور وإخفاء وحركة تناسب الأداء على Android TV.

## المعايير غير القابلة للتفاوض

يجب أن يظل Android TV DPAD واضحاً وقابلاً للوصول في كل ثيم. تستهدف التخطيطات 1920×1080 أولاً، مع دعم 1280×720 و3840×2160. لا تستخدم حركات ثقيلة أو إعادة تركيب غير ضرورية، ولا تكرر بيانات IPTV بين الثيمات.
